# SLS-0004 — Design Filters

Status: Accepted  
Version: 1.0  
Authority: Spider Labs Architecture  
Depends On: SLS-0001, SLS-0002, SLS-0003

## Purpose

This specification defines the questions every feature, architecture change, and implementation decision must pass before acceptance.

## Filters

### DF-001 — Trust

Does this increase trust?

### DF-002 — Ownership

Does this preserve user ownership?

### DF-003 — Explainability

Can this be explained to the user?

### DF-004 — Repeatability

Can this be repeated with the same inputs and recorded configuration?

### DF-005 — Inspection

Can this be inspected before output is accepted?

### DF-006 — Preservation

Does this preserve the original Specimen?

### DF-007 — Ten-year durability

Would this still make sense if Spider Labs exists in ten years?

### DF-008 — Product fit

Does this belong in Compound?

If not, defer it.

### DF-009 — Catalyst independence

Can another Catalyst implement this without changing the architecture?

### DF-010 — Human agency

Does this reduce manual work without reducing human agency?

## Closing statement

Spider Labs values refinement over automation.

Software should amplify human judgment, not replace it.

Trust is earned through preservation, transparency, and repeatability.
